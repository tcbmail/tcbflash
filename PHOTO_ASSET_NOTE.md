# Photo asset note

The biography brief references a user-provided photo archive. Those image bytes currently live outside the GitHub workspace and are **not yet present on this branch**.

Do not block the rebuild on this and do not ask Ben to organize, relabel, or re-upload photographs. He has already done the emotionally expensive part of collecting them.

For the implementation pass:

- build the site so real documentary photographs can be inserted cleanly without redesigning the layout;
- if no usable local image assets are present at execution time, prefer a strong typographic/editorial treatment rather than stock photography, AI-generated fake history, gradients, generic illustrations, or fake archival imagery;
- do not fabricate captions, dates, properties, or events;
- keep image components/data centralized so the curated photos can be dropped in afterward with minimal code churn;
- a photo-free first implementation is acceptable if the alternative is inventing imagery or blocking the entire rebuild.

The design must still feel intentional without photographs. Photos are evidence and texture, not a crutch for the information architecture.
